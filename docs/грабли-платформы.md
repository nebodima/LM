## Расширение и безопасный режим

- **Расширение из файла ставится в безопасном режиме** (27.09.2026). В нём: `ИнтернетПочта.Подключиться` — «Установлен
  безопасный режим»; временные файлы запрещены; `УстановитьПривилегированныйРежим(Истина)` молча не действует —
  привилегированное чтение своего регистра у сотрудника давало AccessDenied, а `Попытка` его глушила (недоделка 20).
  Правило: читать только то, на что есть право в роли; с файлами — в памяти (`ДвоичныеДанные`); отказ показывать
  (журналы продукта говорят администратору, что снять), в инструкции — снять флажок «Безопасный режим».
- **Модуль сеанса расширения в безопасном режиме не применяется** (28.09.2026): ни `&После("УстановкаПараметровСеанса")`,
  ни при начале сеанса; при каждом входе — «Ошибка применения расширения конфигурации» (`ConfigExtensionApplyError`).
  У УЗ_ext модуля сеанса нет, параметры сеанса ставит код.
- **Параметр сеанса расширения в условии роли — мина** (28.09.2026, S04): в COM, фоне, регламентном и HTTP-сеансе его
  никто не ставит, и любое чтение падает «неинициализированного значения параметра сеанса» — даже у администратора.
  Граница просмотра кассы — регистр `УЗ_ГраницаПросмотраКассы` + коррелированный подзапрос в условии
  (`Т ГДЕ ИСТИНА В (ВЫБРАТЬ ПЕРВЫЕ 1 ИСТИНА ИЗ … ГДЕ Т.Дата >= Г.НачалоПросмотра)`). Аудит `права_роли` ловит.
- **`DefaultRoles` расширения = права всем** (28.09.2026): при «Использовать основные роли для всех пользователей»
  роль получает каждый пользователь БП/УТ; `РольДоступна` её не видит, `ПравоДоступа` и запросы — видят. У УЗ_ext
  `<DefaultRoles/>`; аудит `права_роли` + мутация.
- **Право роли расширения на объект хозяина в безопасном режиме срезается** и оповещает каждого пользователя при входе
  (28.09.2026, сценарии ролей).
- **Свои StyleItems расширение держит, но**: схема СКД расширения их не видит («Исключение XDTO» при загрузке Template.xml —
  в СКД цвет числом); на клиенте `ЦветаСтиля`/`ШрифтыСтиля` нет («Переменная не определена»); в COM и фоне стиль «авто»
  (−1,−1,−1) — значение брать из `Метаданные.ЭлементыСтиля` (28.09.2026, аудит `цвета`).
- Своё имя не должно совпадать с именем хозяина/платформы: процедура общего модуля `Сообщить` — «уже определена»;
  переменная `Пользователи = …` (имя общего модуля БСП хозяина) компилируется, а при выполнении — «Поле объекта
  недоступно для записи» (27.09.2026, аудиты `ноль_бсп`, `свойства_формы`).
- Расширение не меняет форму отчётов хозяина по умолчанию (у типовых — форма БСП): каждому отчёту — `УЗ_ФормаОтчета`,
  стандартные «Настройки…/Изменить вариант…» отключены (27.09.2026).

## Права и RLS

- **RLS на общий журнал документов не действует**, если в журнал входят документы без права «Чтение» (28.09.2026) —
  ограничение ставить на сами документы.
- **Экспортную функцию модуля менеджера обработки можно вызвать без права «Использование»** — в начале таких функций
  `ВыполнитьПроверкуПравДоступа` (28.09.2026).
- **Права на поля**: «Просмотр» = Ложь у реквизита — элемент формы не создаётся, `Элементы.X.Видимость` в модуле
  роняет открытие формы (ловит только открытие, не /CheckModules); `ГДЕ ЛОЖЬ` на чтение поля закрывает и
  `ПолучитьОбъект()`. СКД молча выкидывает поля без «Просмотр» — зарплата педагога сделана страницей «Мои уроки»,
  а не отчётом (28.09.2026).
- «Изменение» регистра без «Чтения» платформа считает и чтением без ограничения (29.09.2026, аудит `права_роли`).
- **COM-сеанс ≠ вход в программу**: с минимальным набором ролей COM работает, веб/тонкий — «Нарушение прав доступа» при
  старте хозяина. Наборы ролей хозяина — `docs/роли_и_права.md`, проверены входом в веб-клиент (28.09.2026).
- Причину «Нарушение прав доступа!» платформа не называет — читать `1Cv8Log\*.lgp` (событие `_$Access$_.AccessDenied`)
  с запомненной позиции; `ВыгрузитьЖурналРегистрации` по COM висит (27.09.2026, `сеанс.события_журнала`).

## Загрузка и агент конфигуратора

- **Агент молча отбрасывает загрузку** (28–29.09.2026): при XDTO-ошибке в одном файле (`StdPicture.FillForm`,
  `FillFromFillingValue` у реквизита ТЧ, версия формата Help.xml не как у Form.xml) `config load-files` отвечает «ок»
  и не грузит НИЧЕГО; /CheckModules потом проверяет старый код и зелёный. Причину называет только пакетная загрузка
  с `/Out`. Гейт деплоя — выгрузка обратно и сверка с src_ext (`tools/сверка_выгрузки.py`), аудит `схема_платформы`.
- **Молча выбрасывается и часть свойств** (28.09.2026): картинка на несуществующую `CommonPicture` → `<xr:Ref>0`,
  `<Indexing>` у реквизита ТЧ, `MainFilterOnPeriod=true` у регистра, подчинённого регистратору, `<Client>` у общего
  модуля, блок `<Help>` в Form.xml (справка — только `Ext/Help.xml`). Свойства по умолчанию (`ShowGrid=false`,
  `HorizontalStretch=true` у таблицы) в XML не писать — выгрузка их опускает, сверка краснеет.
- **`UnknownError` после `update-db-cfg`** (28.09.2026): на следующий `load-files` агент отвечает `Ошибка UnknownError`
  без « - текст» — старый разбор считал это успехом. `disconnect-ib`/`connect-ib` не лечат — только перезапуск агента.
- **Агент держит базу, пока SSH-сессия после `connect-ib` открыта** — пакетный /CheckModules рядом падает «Ошибка
  блокировки ИБ для конфигурирования»; на время проверки `common disconnect-ib` (28.09.2026).
- **`/AgentBaseDir` — только ASCII-путь** и грузить только из-под него (из `LESSONS_MANAGER\src_ext`, `%TEMP%` —
  «Directory access violation»): деплой держит зеркало `%TEMP%\uz_agent\<база>\src` (28.09.2026).
- `/LoadConfigFromFiles … /CheckModules` в одном запуске — ложно-зелёная проверка; два пакетных конфигуратора в одну
  базу — «Ошибка блокировки» (общие правила).
- Агенты без срока жизни копятся: 15 процессов 1cv8 → «Ключ защиты программы больше не доступен» (0xC0000409) у прогонов
  (28.09.2026). Сторож простоя 10 мин, `tools\агенты.ps1 -Список/-Остановить`.
- Порт агента 1543 занят агентом DO_3 — свои агенты на 1546–1560, владелец порта сверяется по pid.

## Лицензии и ключ HASP

- **Лицензии общие с «Путевыми листами» и DO_3.** 6 параллельных агентов с базами и веб-стендами — «402 Payment
  required» и у соседей (28.09.2026). Держать 2–3 своих сеанса; веб-стенд поднимать только на время проверки.
- **Веб-сеанс файловой базы держит лицензию и исполняет фоновые задания** — прогон с двойниками рядом ловил «Ключ
  защиты больше не доступен» (29.09.2026). Стенд 8095 после проверки останавливать.
- Каждая свежая загрузка веб-клиента — новый сеанс, прошлый висит до таймаута (28.09.2026).
- После перезагрузки ПК 1С однажды не видела ключи HASP (Status −10) — проверять до запуска работ (28.09.2026).
- Проверенный предел клиентов — 14 (9 COM + 5 процессов 1cv8); «до отказа» не проверять — уронит чужие сеансы.
- Лицензии забирают и сеансы кластера других проектов (8 COM) — агент не входит по SSH («Authentication failed:
  transport shut down»), держатель итерации ждёт (29.09.2026). При «нет лицензии» — ждать, не плодить попытки.

## Данные и COM-тесты

- **`ОбменДанными.Загрузка = Истина` при удалении документа оставляет его движения** (28.09.2026) — сироты
  «<Объект не найден>» в отчётах. `сеанс.удалить_объект` снимает наборы движений сам; каждый тест проверяет «после
  теста нет новых сирот»; `tools/убрать_сирот.py`.
- **Время суток в тестах** (29.09.2026): прогон в 00:03 дал провалы — урок «сегодня в 0:05» ещё не начался, ПКО «сегодня»
  в будущем. Сеансы тестов закреплены поясом `Etc/GMT±N` около 12:00 дня тестов (`сеанс.закрепить_время`); даты — от
  `сеанс.сегодня()/сейчас()`. Фоновые задания идут в поясе базы.
- COM: наивный `datetime` сдвигается по поясу — только с `tzinfo=utc`; пустая дата приходит `0100-01-01`; `Формат` и
  `ТипЗнч` через соединение недоступны; выходные параметры не возвращаются.
- **Файловая база: фоновое задание из COM не исполняется** — вечно «Задание выполняется»; исполнитель — клиентский
  сеанс или веб-сервер. В тесте задание отменять и звать метод напрямую (28.09.2026).
- Два сеанса в одной файловой базе — «Конфликт блокировок… не удалось заблокировать таблицу»; параллелить — на копии
  `1Cv8.1CD` (двойник `UZ_*_2`, 1–4 с на NVMe) (28.09.2026).
- Запись файловой базы вне транзакции — 10–20 мс фиксации; удаление элемента справочника без режима загрузки — 40–48 мс
  (подписки хозяина на «все справочники»), с загрузкой — 9 мс. Уборка тестов — пакетом в транзакции (29.09.2026).
- Первый СКД/`ФабрикаXDTO` в сеансе — 3–4 с на УНФ; COM-сеанс БП — ~2,2 с кода хозяина при старте; открытие базы в
  процессе ~3,5 с — пока жив хоть один сеанс, новый 2,5 с вместо 6 (27–28.09.2026).
- В COM-сеансе и фоне палитры стиля нет (см. выше); python 3.11 `traceback.format_exc()` падает на кириллице с «^^^» —
  кадры печатать самим.
- `ПолучитьОбъект` отдаёт данные из кэша сеанса — после правки документа другим сеансом `Прочитать()` перед записью,
  иначе «несоответствие версии» (28.09.2026, `фабрика.уборка_документа`).

## Формы, веб-клиент, интерфейс

- **Веб-клиент не держит ширины**: `<Width>` у таблицы при `AutoMaxWidth` по умолчанию её не расширяет (упирается в сумму
  колонок); фиксированная таблица рядом с растягиваемой тоже не получила заданного (29.09.2026). Надёжнее убрать лишние
  колонки, чем подбирать ширины; каждую пробу — снимком. Картинка в заголовке колонки съедает 2–3 знака.
- `НачалоНедели`/`КонецНедели` для понедельника в веб-клиенте давали неверные даты — неделю считать своей функцией.
- Команды автозаполнения платформа ставит ПЕРЕД явно размещёнными кнопками — «Создать» первой, свои — явно.
- Переменная модуля формы с именем свойства формы (`Доступность`, `Заголовок`) — «Несоответствие типов» при открытии
  (аудит `свойства_формы`).
- `ПриИзменении` ТАБЛИЦЫ срабатывает уже на пустой строке — вызов сервера обрывает ввод; пересчёт вешать на поле
  колонки и `ПослеУдаления`.
- Колонка динамического списка на табличную часть платформой не создаётся — `Элементы.X` в `ПриСозданииНаСервере`
  роняет форму у всех (ловит только открытие).
- Тумблер показывает `EditFormat`, а не `Format` (аудит «EditFormat без Format» тумблеры не судит).
- Тест-менеджер: запускать в ПУСТОЙ базе (в типовой — 18 с старта и модальные окна БСП), имя процедуры = глобальный
  метод клиента (`ВвестиЗначение`) ломает модуль формы только на клиенте (`tools/сценарии/README.md`, 28.09.2026).
- Регламентные задания файловой базы исполняет только клиентский сеанс или веб-сервер — на копиях без клиента граница
  просмотра кассы живёт до следующего входа.

## Макеты и печать

- Макет, собранный через COM (`СериализаторXDTO`), пишет тексты ячеек с языком `#` и без `<languageSettings>` — после
  загрузки тексты пропадают; лечение — `lang #`→`ru` (`tools/макеты/макет_рко.py`, 27.09.2026).
- Печать в подменю «Печать» хозяина без вызовов БСП: `Печать(...)` с сигнатурой БСП в менеджере + `ОткрытьФорму`
  формы печати хозяина (имя даёт `УЗ_Среда.ФормаПечатиХозяина`); из COM `ПараметрыПечати` — только Структура.
- Ширина макета РКО: сумма колонок 96 — А4 книжный и окно веб-клиента 1280 без прокрутки (было 117).
