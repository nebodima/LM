# Роли и права «Учёта занятий» (расширение УЗ_ext)

Проверено 28.09.2026 на УНФ 3.0.12, Бухгалтерии предприятия 3.0 и Управлении торговлей 11.5 (копии
`UZ_UNF_C`, `UZ_BP_B`, `UZ_UT_B`): тест `tools\тесты\тест_права.py` — живые сеансы менеджера и руководителя
с ролями из таблиц ниже, каждый отказ подтверждён журналом регистрации; вход менеджера в веб-клиент во всех
трёх конфигурациях; в УНФ под менеджером открыты список и форма урока, карточка педагога, «Движения документа»,
общий журнал, РКО (новый и выплата зарплаты), календарь, панель ученика, в БП — список уроков: без «Нарушения
прав доступа» от «Учёта занятий».

## Две роли — как в типовых

| | Менеджер — «Учёт занятий: менеджер» (`УЗ_ОсновнаяРоль`) | Руководитель — «Учёт занятий: руководитель» (`УЗ_Руководитель`) |
|---|---|---|
| Уроки, календарь, помощник и изменение уроков, панель ученика | да | да |
| Ученики и педагоги, группы, предметы, тарифы и цены, абонементы, скидки, дисконтные карты, бонусы, графики педагогов, списание остатков, справочники кассы | да | да |
| Приход денег, перемещение денег | да | да |
| Расход денег (РКО) | только «Касса ученики» (возврат ученику) | все виды |
| Выплата зарплаты, прочий расход, документ «Дополнительные расходы» | нет | да |
| Расходы урока (страница «Доп. расходы» в уроке) | да | да |
| Ставки педагогов, начисления педагогам, расчёт зарплаты, отчёт «Расчёты по зарплате» | нет (ставку и начисления в уроке и карточке педагога не видит) | да |
| Отчёты: взаиморасчёты, явки, аналитика по ученикам, бонусы и карты, ведомость по кассе для менеджеров, движения документа | да | да |
| Полная ведомость по кассе, отчёт по расходам | нет | да |
| Массовая выгрузка и загрузка фото учеников | нет | да |
| Настройки учёта занятий | только чтение | чтение и изменение |
| Даты запрета изменения | только чтение | чтение и изменение |
| Свои напоминания | да | да |
| Настройки почты (пароль SMTP) | нет | нет — только администратор с «Полными правами» |

Удаление (не пометка) — ни у одной роли: помеченное удаляет администратор.

Что менеджер всё-таки видит и почему:
* **Ставки педагогов читает код урока**, а не человек: при записи урока начисление педагогу считается по ставке.
  Расширение из файла работает в безопасном режиме, а в нём привилегированный режим не действует — поэтому
  у роли менеджера есть право «Чтение» справочника ставок без права «Просмотр»: справочника нет в его интерфейсе,
  открыть его нельзя, поле ставки и страница «Начисления педагогу» в уроке и карточке педагога скрыты.
* **РКО выплаты зарплаты** менеджер видит в кассовом журнале и открывает только для просмотра (он отвечает за
  кассу), но создать, изменить или провести его не может.
* Регистры зарплаты и расходов менеджер только пополняет движениями своих уроков, прочитать их не может.

### Зарплата в уроке, касса, движения, напоминания (повторный аудит 28.09.2026)

* **Права на поля роли менеджера** (как в ЗУП): «Начислено педагогу» и табличная часть «Начисления педагогу»
  урока, суммы ставки («Оплата за занятие», «за час», «с человека», «% с оплаты») — без «Просмотр» и
  «Редактирование»: их нет в форме, в списке и в «Настроить список» (проверено в веб-клиенте). «Ставка педагога»
  в уроке и карточке физ. лица — без «Редактирование»; «Просмотр» оставлен: без него платформа не создаёт элемент
  формы, а модули урока и карточки прячут его по имени — форма урока у менеджера не открывалась.
* Ограничение чтения поля («ГДЕ ЛОЖЬ» на поле, как в типовых для регистров) для урока не годится: платформа тогда
  не даёт прочитать урок целиком — менеджер не откроет и не проведёт урок (проверено). Запросом поля менеджер
  прочитать может, но запросов в его интерфейсе нет; универсальный отчёт хозяина — отдельная роль
  («Использование универсального отчёта»), в профили менеджера её не включать.
* **Ручные начисления** (доплата с комментарием без «#», «Не изменять») меняет только тот, кому доступна
  зарплата: подписка `УЗ_ЗарплатаУрокаПередЗаписью` сравнивает их с уроком в базе и отказывает с причиной; в
  копию урока менеджером они не переносятся.
* **Касса менеджера — за его неделю**: в кассовом журнале ограничение роли по дате (граница — скользящий запрет
  «старше N дней» из «Даты запрета изменения», её ставит форма журнала). Общий журнал и списки ПКО/РКО пока
  показывают и старую кассу — нужно ограничение на сами документы (план — docs/проверки.md).
* **Движения регистров** менеджер вручную не правит (нет «Редактирование»), проведение пишет их само.
* **Напоминания**: свои и общие (о задолженности) — любому; чужие завершить или поставить другому — руководителю.
  Проверку задолженности всей базы запускает регламентное задание или руководитель.
* **Параметры сеанса расширения**: «Песочница почты» (тесты на копиях — письма не уходят, пишутся в журнал) — её
  может включить любой, она только запрещает отправку; «Начало просмотра кассы» — ставит код.

### Как ограничена выплата зарплаты

Ограничением доступа на уровне записей в роли менеджера: права «Добавление», «Изменение» и «Удаление» документа
«Расход денег» даны с условием `ВидОперации = ЗНАЧЕНИЕ(Перечисление.УЗ_ВидыОпераций.КассаУченики)`. Платформа
проверяет его при любой записи — из формы, обработки или внешнего соединения, — отказ пишется в журнал
регистрации («Нарушение прав доступа»). Форма РКО у менеджера предлагает только «Касса ученики», а выплату и
прочий расход открывает только для просмотра. У руководителя условия нет; у пользователя с обеими ролями права
складываются — он работает как руководитель.

### После установки новой версии

Обновление данных «Учёта занятий» пишет общие настройки, кассы и документы — это права руководителя.
Первым после обновления журнал уроков должен открыть руководитель или администратор; менеджер до этого видит
сообщение «Учёт занятий ждёт подготовки своих данных после обновления: руководителю или администратору открыть
журнал уроков».

### Персональные данные учеников

История изменений справочника «Физ. лица» (ученики, родители, педагоги) выключена: новые версии с датами
рождения, телефонами и заметками не записываются. Версии, записанные до этого обновления, платформа сама не
удаляет. Массовая выгрузка фото — только у руководителя.

## Текст для инструкции покупателю

> **Как дать сотрудникам доступ к «Учёту занятий».**
> В «Учёте занятий» две роли: **«Учёт занятий: менеджер»** — администратор студии на ресепшене (уроки, ученики,
> абонементы, приём денег, возврат денег ученику, календарь, отчёты по урокам и явкам) и **«Учёт занятий:
> руководитель»** — всё, включая зарплату педагогов, расходы, настройки, даты запрета и все отчёты. Роли
> выдаются через профили групп доступа.
>
> **Способ 1 — сотрудник уже работает в программе.** Добавьте роль в профиль, по которому он работает:
> 1. Откройте раздел **Администрирование** (в УНФ — **Настройки → Администрирование**, в УТ —
>    **НСИ и администрирование → Администрирование**) → **Настройки пользователей и прав** →
>    **Профили групп доступа**.
> 2. Откройте профиль сотрудника. Если роли профиля изменить нельзя (профиль поставляемый) — нажмите
>    **Скопировать**, назовите копию, например «Продажи и учёт занятий», и дальше работайте с копией.
> 3. На закладке с ролями (**Разрешенные действия**) отметьте **«Учёт занятий: менеджер»** (руководителю —
>    **«Учёт занятий: руководитель»**). Нажмите **Записать и закрыть**.
> 4. Если делали копию — в **Группы доступа** переключите группу сотрудника на новый профиль.
>
> **Способ 2 — отдельные профили только для «Учёта занятий».** В **Профили групп доступа** нажмите **Создать**,
> назовите профиль «Учёт занятий: менеджер» и отметьте роли из таблицы для вашей программы и роль
> **«Учёт занятий: менеджер»**. Так же создайте профиль «Учёт занятий: руководитель» — те же роли программы и роль
> **«Учёт занятий: руководитель»**.
>
> | Программа | Роли программы (для обоих профилей) |
> |---|---|
> | Управление нашей фирмой 3.0 | Базовые права БСП; Базовые права БТС; Базовые права приложения; Запуск тонкого клиента; Запуск веб-клиента; Вывод на принтер, в файл, в буфер обмена; Сохранение данных пользователя |
> | Бухгалтерия предприятия 3.0 | Базовые права БСП; Базовые права: Бухгалтерия предприятия; Базовые права по электронным документам; Базовые права Интернет-поддержки пользователей; Базовые права БТС; Просмотр организаций; Запуск тонкого клиента; Запуск веб-клиента; Вывод на принтер, в файл, в буфер обмена; Сохранение данных пользователя |
> | Управление торговлей 11 | Базовые права БСП; Базовые права УТ; Чтение организаций и банковских счетов организаций; Запуск тонкого клиента; Запуск веб-клиента; Вывод на принтер, в файл, в буфер обмена; Сохранение данных пользователя |
>
> Затем **Группы доступа → Создать**: группа «Учёт занятий: менеджеры» с профилем «Учёт занятий: менеджер» и
> группа «Учёт занятий: руководители» с профилем «Учёт занятий: руководитель»; на закладке **Участники** добавьте
> сотрудников. **Записать и закрыть.**
>
> Настройки почты меняет только администратор (профиль «Администратор»). После установки новой версии
> «Учёта занятий» первым откройте журнал уроков под руководителем или администратором.

## Имена ролей в конфигураторе

Для проверки и для баз без профилей групп доступа.

| Конфигурация | Роли основной конфигурации | Менеджер | Руководитель |
|---|---|---|---|
| УНФ 3.0 | `БазовыеПраваБСП`, `БазовыеПраваБТС`, `БазовыеПраваПриложения`, `ЗапускТонкогоКлиента`, `ЗапускВебКлиента`, `ВыводНаПринтерФайлБуферОбмена`, `СохранениеДанныхПользователя` | `УЗ_ОсновнаяРоль` | `УЗ_Руководитель` |
| БП 3.0 | `БазовыеПраваБСП`, `БазовыеПраваБП`, `БазовыеПраваЭД`, `БазовыеПраваИПП`, `БазовыеПраваБТС`, `ЧтениеОрганизаций`, `ЗапускТонкогоКлиента`, `ЗапускВебКлиента`, `ВыводНаПринтерФайлБуферОбмена`, `СохранениеДанныхПользователя` | `УЗ_ОсновнаяРоль` | `УЗ_Руководитель` |
| УТ 11.5 | `БазовыеПраваБСП`, `БазовыеПраваУТ`, `ЧтениеОрганизацийИБанковскихСчетовОрганизаций`, `ЗапускТонкогоКлиента`, `ЗапускВебКлиента`, `ВыводНаПринтерФайлБуферОбмена`, `СохранениеДанныхПользователя` | `УЗ_ОсновнаяРоль` | `УЗ_Руководитель` |

`БазовыеПраваБТС` (УНФ) и `БазовыеПраваБП` (БП) обязательны: без них хозяин не пускает в программу
(«Запуск приложения невозможен: Нарушение прав доступа» — чтение констант `РежимИспользованияИнформационнойБазы`
и `ДатаТекущейВерсии` при старте); COM-соединение этого не замечает, поэтому наборы проверены входом в веб-клиент.
Имя `УЗ_ОсновнаяРоль` прежнее — у покупателей она уже стоит в профилях; после обновления она становится
менеджерской: зарплата, расходы, настройки и даты запрета из неё ушли в «Учёт занятий: руководитель».
Сотрудникам, которые вели зарплату под прежней ролью, добавьте роль руководителя.
`ЗапускВнешнегоСоединения` тест выдаёт только себе (COM-подключение); покупателю она не нужна.
28.09.2026 вход менеджера с этим набором в веб-клиент копии УНФ `UZ_UNF_C` отказал «Недостаточно прав для работы с
таблицей РегистрСведений.КурсыВалют.СрезПоследних» — вошёл после добавления роли `ЧтениеКурсовВалют`. Перед выпуском
инструкции проверить на чистой УНФ, нужна ли она в наборе (зависит от начальной страницы и настроек хозяина).

Администратор с ролью «Полные права» работает со всем, включая настройки почты; наши роли ему не нужны.

## Что проверяет код, а не роль

* `УЗ_Общий.ДоступнаЗарплата()` — право изменения расчёта зарплаты (руководитель, «Полные права»). По нему
  форма урока прячет ставку и страницу «Начисления педагогу», карточка педагога — ставку, форма РКО — выплату
  и прочий расход.
* `УЗ_ОбработкаФото` — выгрузка и загрузка фото начинаются с `ВыполнитьПроверкуПравДоступа("Использование", …)`:
  экспортную функцию модуля менеджера платформа даёт вызвать и без права на обработку (проверено тестом).
* Отчёт «Движения документа» показывает только регистры, которые пользователь может читать.
* Обновление данных (`УЗ_ОбновлениеДанных`) идёт только у того, кто может записать настройки и версию данных.

## Как проверить

    pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_UNF_C -Пользователь Администратор -БезСборки -НесмотряНаАудит
    python tools\прогон.py --база=C:\1c_bases\UZ_UNF_C --пользователь=Администратор --тест=права
    python tools\прогон.py --база=C:\1c_bases\UZ_BP_B --пользователь=1 --тест=права
    python tools\прогон.py --база=C:\1c_bases\UZ_UT_B --пользователь=Admin --тест=права

Отказы прав тест берёт из журнала регистрации (`_$Access$_.AccessDenied`, файл `1Cv8Log` базы) и печатает, какое
право на какой объект не выдано. Ожидаемый отказ засчитывается, только если действие упало и в журнале есть отказ
именно на нужный объект. Офлайн-аудит `tools\аудиты\права_роли.py` сверяет обе роли с этой матрицей по исходникам.
Мутации: блок `Document.УЗ_ПриходДенег` убран из роли → «менеджер проводит приход денег — Нарушение прав доступа»;
менеджеру выдано право на `Document.УЗ_РасчетЗарплаты` → красные «прочитать/записать расчёт зарплаты» и аудит
`права_роли`.
