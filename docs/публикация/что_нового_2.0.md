# «Учёт занятий» 2.0: новая версия «Учёта уроков»

> Для карточки, рассылки прежним покупателям и ответов в обращениях. Источники: `docs/план_перевода_в_расширение.md`,
> `docs/аудит_полный_2026-09-28.md` (раздел 7 — решения по правилам учёта), `docs/ошибки_из_справки_2026-09-28.md`,
> `docs/недоделки.md`, `docs/проверки.md` (тесты, которыми подтверждены исправления).

## Коротко

«Учёт занятий» 2.0 — новая версия продукта «Учёт уроков». «Учёт уроков» была отдельной конфигурацией
(LessonsManagement 2.3.3.66) на Библиотеке стандартных подсистем (БСП) 3.1. «Учёт занятий» 2.0 — расширение, которое
ставится в вашу рабочую базу 1С:Управления нашей фирмой 3.0, 1С:Бухгалтерии предприятия 3.0 или 1С:Управления
торговлей 11.5. Учёт студии и учёт организации — в одной базе.

**Новая версия ставится на чистые данные: перенос из «Учёта уроков» (УчетУроков) не предусмотрен.** Структура
данных исправлена (например, длительность урока хранилась датой, а не числом), и прежние данные в неё не ложатся
без пересчёта. Это решение, а не недоделка. Промежуточных выпусков расширения не было: 2.0 — первая версия
«Учёта занятий».

## Форма поставки

| | «Учёт уроков» | «Учёт занятий» 2.0 |
|---|---|---|
| Что это | отдельная конфигурация | расширение (`.cfe`) к типовой конфигурации |
| Где работает | своя база | база УНФ 3.0, БП 3.0, УТ 11.5/11.6, КА 2.5 или ERP 2.5 (не базовые версии) |
| Библиотека стандартных подсистем | встроена (своя копия БСП 3.1) | не используется: ни кода, ни объектов БСП; печать встраивается в подменю «Печать» программы |
| Платформа | режим совместимости 8.3.14 | 8.3.24 и выше |
| Модальные окна | 13 вызовов | нет (типовые их запрещают) |
| Роли | одна `LM_Менеджер` | три: «Учёт занятий: менеджер», «Учёт занятий: руководитель» и «Учёт занятий: педагог» |
| Справка | у уроков, абонементов, физ. лиц не было | F1 в формах продукта |

## Что заменено своим

- Даты запрета изменения — свой регистр: общая дата, дата для отдельного пользователя и скользящая граница
  «старше N дней».
- Напоминания — свои: команда «Напомнить», список «Оповещения», всплывающие окна.
- Форма отчётов, печать ПКО и РКО, подготовка данных после обновления — свои, без БСП.
- Печать ПКО: реквизиты организации (ИНН, КПП, ОКПО, наименование) берутся из её карточки; счета не
  впечатываются в код, графы остаются для бухгалтера. Добавлены РКО (КО-2) и печать начисления бонусов.
- Почта: письма должникам ученику и ответственному родственнику через ваш почтовый сервер; настройки почты
  с проверочным письмом. В «Учёте уроков» модуль почты нигде не вызывался.
- Кассы, статьи движения денег, приход и расход денег — свои объекты расширения: они не делают проводок в
  бухгалтерии вашей программы.

## Правила учёта (решения 28.09.2026, как в типовых)

- Урок нельзя провести раньше его начала; будущий урок записывается планом.
- Урок по абонементу стоит цену абонемента, делённую на число занятий; без абонемента — по тарифу.
- Приостановка абонемента — с даты начала включительно по дату возобновления; срок абонемента продлевается
  на дни приостановки.
- Неявка с отметкой «К оплате» расходует занятие абонемента; явка без «К оплате» — бесплатное занятие, абонемент
  не расходует.
- Урок, на который никто не пришёл, не начисляет педагогу «за занятие» и «за час»; «с человека» — по явке.
- Возврат денег по уроку возвращает только деньги, часы второй раз не уменьшает.
- Новый вид расхода «Прочий расход»: аренда и прочие траты не уменьшают долг педагогу.
- Расчёт зарплаты — ведомость за период с фиксацией вошедших уроков; выплата — на основании проведённого
  расчёта и только педагогу.
- Деньги учеников учитываются раздельно по организациям.
- Длительность урока — с точностью до минуты (40 минут — 0,6667 ч), деньги округляются до копеек.
- Касса не уходит в минус ни расходом, ни перемещением.
- Отдельного правила «9-й урок со скидкой» нет — скидки только через справочник скидок.

## Исправленные ошибки

Найдены аудитом кода, перенесённого из «Учёта уроков», и исправлены; каждое исправление закреплено тестом
(`docs/проверки.md`).

- Зарплата могла попасть в два расчёта — теперь урок входит только в один.
- Бонусы списывались с пустой карты — теперь пустая или недостаточная карта не принимается.
- «Списание остатков» писало часы не в тех единицах и с обратным знаком против урока.
- Цена урока не пересчитывалась при смене часов, даты, тарифа; скидка применялась вне срока и могла сделать
  сумму отрицательной.
- «Изменение уроков» не обновляло движения уроков.
- Строка «К оплате» без тарифа проводилась с нулевой суммой — теперь отказ «тариф не указан».
- Пересечения уроков по педагогу и помещению только сообщались — теперь урок не проводится.
- Проведение урока, оплаты, перемещения, расчёта зарплаты не блокировало остатки — одновременные документы
  могли перерасходовать абонемент, бонусы или кассу.
- Возврат денег из карточки ученика не проводился.
- Ежедневная проверка должников обращалась к таблице вместо строки таблицы — переписана, оповещение и письмо
  о долге проверены тестом.
- «Переместить деньги» в расчёте зарплаты вызывало несуществующую функцию.
- Отчёт «Аналитика по ученикам» обращался к несуществующим полям прихода денег.
- Выгрузка фото шла в жёстко заданную папку `c:\temp\`.
- Панель ученика: падение после выбора дат, «Проведено» при ошибке проведения, неработающий перевод из группы.
- Абонемент: копия наследовала приостановки и активацию; закрытие окна приостановки крестиком добавляло
  приостановку.
