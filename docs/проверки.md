# Опись проверок «Учёта занятий» (УЗ_ext)

Опись сверяет сам аудит `скрипты` (`tools/аудиты/скрипты.py`): каждый аудит и каждый COM-тест
на диске обязан быть назван здесь, каждый путь `tools/…/*.py` в `docs/*.md` — существовать.
Добавил проверку — допиши строку сюда, иначе все_аудиты покраснеет.

## Как запускать

    python tools/аудиты/все_аудиты.py              # все офлайн-аудиты src_ext, бюджет ≤ 5 с (печатается)
    python tools/аудиты/самотест.py                # каждая проверка обязана краснеть: мутации на фикстурах
    python tools/прогон.py                         # COM-тесты tools/тесты/тест_*.py на УНФ, БП, УТ
    python tools/прогон.py --база=C:\1c_bases\UZ_UNF_B --пользователь=Администратор --тест=аудит_данных
    pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_UNF_D          # загрузка расширения в свою копию
    pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_UNF_D -НесмотряНаАудит   # пока аудиты красные (262)
    python tools/убрать_сирот.py --база=C:\1c_bases\UZ_UNF_D            # сироты в регистрах УЗ_: отчёт
    python tools/убрать_сирот.py --база=C:\1c_bases\UZ_UNF_D --исправить  # …и уборка
    python tools/мутации_проверок.py --база=C:\1c_bases\UZ_UNF_D        # COM-проверки краснеют (8 мутаций, ~3 мин)
    pwsh -File tools\мутации_гейта.ps1 -База C:\1c_bases\UZ_UNF_D       # гейты деплоя краснеют (~2 мин)

Самотест: чистые фикстуры (`tools/аудиты/фикстуры`) — 0 замечаний во всех аудитах; в копию подкладывается
ровно одна ошибка — нужный аудит даёт ровно одно замечание; «почти ошибки» — ни одного. Аудит без мутации
самотест считает провалом. Фикстуры с 28.09 — документ, справочник, регистр, общий модуль, **отчёт со схемой
СКД и обработка с формой** (78 мутаций, 5 — на отчёт и обработку: обработчики, элементы_форм, bom,
повторы_тегов, права_роли).

## Деплой (tools/деплой.ps1): гейты и время

Порядок: офлайн-проверки параллельно (проверка src_ext, все аудиты, самотест аудитов — самотест только если
`tools/аудиты` изменились с последнего зелёного: кэш по отпечатку содержимого) → **красное — СТОП до загрузки**
(исключение — ключ `-НесмотряНаАудит`, печатается ПРЕДУПРЕЖДЕНИЕ) → на каждую базу: замок → загрузка →
`/CheckModules` (до применения) → применение → отметка деплоя.

| Что | Как устроено |
|---|---|
| разбор результата | не по словам. Пакетная загрузка/применение — зелёные, только если код 0 **и журнал /Out пуст** (при успехе платформа молчит, любой текст печатается целиком). `/CheckModules` — код 0, «Синтаксических ошибок не обнаружено» и ни одной строки `{Модуль(стр,кол)}:`. Агент — строка ответа вида `Ошибка ConfigFilesError - …` |
| таймауты | каждый шаг — 3× своего бюджета, процесс снимается, шаг красный |
| замок | `%TEMP%\уз_прогон\c_1c_bases_uz_unf_d.lock` (для UZ_UNF_D), байт 0 — тот же, что у прогона: деплой и прогон в одну базу не идут одновременно, второй ждёт до 3 мин и печатает ожидание |
| частичная загрузка | отпечаток «длина\|время» файлов прошлой удачной загрузки в эту базу; новые/удалённые файлы, Configuration.xml, другая папка, чужая заливка — полная. Отпечаток снимается перед загрузкой и пишется только после применения: после упавшей загрузки или красного гейта следующий деплой — полный |
| агент конфигуратора | `tools/агент_конфигуратора.py`: папка `%TEMP%\uz_agent\UZ_UNF_D` (ASCII, по имени папки базы), порт — свободный из 1546–1560, владелец порта сверяется по pid (1543 — агент DO_3, 1545 — ras). После `update-db-cfg` перезапуск в фоне. Любой отказ — пакетный конфигуратор. Путь исходников и файла списка с кириллицей агент отвергает («Directory access violation») — тогда пакетно |
| «в базе то, что в src_ext» | `tools/отпечаток_src.py`: деплой пишет отметку (sha256 src_ext) в `%TEMP%\уз_прогон\c_1c_bases_uz_unf_d.деплой.json`; прогон первым пунктом «расширение» сверяет отпечаток рабочей копии с отметкой и ХешСумму УЗ_ext в базе с привязанной первым прогоном. Нет отметки / src изменён после деплоя / расширение перезалито мимо деплоя — красное. `--без-сверки` — осознанно |

Мутации гейта (`tools/мутации_гейта.ps1`, 28.09.2026, база UZ_UNF_D): «Проба = ;» в общем модуле — «проверка
модулей ОШИБКА», в базу не применено; тип реквизита на несуществующий справочник в XML — «загрузка ОШИБКА»
(агент, затем пакетно); «Для И = 1 По 2» без ключа — «СТОП до загрузки». **Не ловится загрузкой** (платформа
молча принимает): неизвестный элемент `<НеверноеСвойство>` в XML и неверное булево `<Hierarchical>неверно`.

Время цикла на UZ_UNF_D (28.09.2026): было 49 с (полная загрузка 12,7 + применение 11 + проверка модулей 19,3 —
три пакетных запуска, модули проверялись после применения). Стало: изменений нет — 2,4 с; частичная (1 файл) —
36 с; полная через агента — 36–41 с; откат на пакетный конфигуратор — 53–63 с. Главное время теперь —
`/CheckModules` 19–20 с (≈12 с старт и загрузка метаданных УНФ + ≈3–4 с на режим), у агента такой команды нет.

## Прогон (tools/прогон.py)

Замок общий с деплоем; ожидание занятой базы печатается и в итоге («ожидание занятой базы N с») — таймаут
на него продлевается, бюджет молча не съедается. Жёсткий таймаут процесса базы — 3× бюджета (135 с) + ожидание:
процесс снимается, база «ТАЙМАУТ». Тест без единой проверки — провал. `аудит_данных` идёт последним: после
уборки всех тестов на чистой базе он обязан быть зелёным. После КАЖДОГО теста `сеанс.py` сверяет число
регистраторов-сирот в регистрах УЗ_ до и после (≈0,05 с, вне бюджета) — прибавилось → красное. Журнал своей
копии — `СВОЯ_UZ_UNF_D.log` (прогоны разных копий не затирают друг друга).

Проверено 28.09.2026 на UZ_UNF_D: `--таймаут=12` — «ТАЙМАУТ: процесс базы снят через 13 с», код 1; деплой
во время прогона ждал замок 15 с с печатью; прогон во время деплоя ждал 30 с («ожидание занятой базы 30 с (вне
бюджета)»). Мутации `tools/мутации_проверок.py` — 8 из 8 краснеют (сироты, точная сумма долга, причина отказа
урока, причина отказа печати, цифры четырёх отчётов, цифры отчёта сотрудника, сверка src, сверка ХешСуммы).
Полный прогон: UZ_UNF_D — 11 из 11 зелёных, 36,6 с; копия УТ UZ_UT_D — 11 из 11, 33,1 с.

Сироты в базах A/B/C/UZ_UT были от `тест_права`: он удалял ПКО и уроки сотрудника с `ОбменДанными.Загрузка =
Истина`, а в этом режиме платформа движения документа НЕ удаляет (опыт на UZ_UNF_D: «движений до 1, после
удаления 1», без Загрузки — 0). Теперь `сеанс.удалить_объект` снимает движения по всем регистрам документа сам.
Мутация (вернуть удаление без снятия движений) — тест_права красный «после теста нет новых сирот».

## Офлайн-аудиты исходников (tools/аудиты, запускатель все_аудиты.py)

| Аудит | Что ловит |
|---|---|
| ноль_бсп | обращения к объектам БСП вне слоя УЗ_Среда (код, XML, запросы, заимствования) |
| зарезервированные_слова | `Для И =`, `Перем Метаданные`, `КАК В` — модуль не компилируется / запрос падает |
| имена | свои объекты без префикса УЗ_, остатки LM_, латиница внутри кириллических имён |
| форм_id | дубли id и имён элементов в Form.xml, битый XML формы |
| модальность | Вопрос(), ОткрытьМодально(), синхронные диалоги — в веб-клиенте падают |
| ссылки_на_метаданные | Справочники.X, таблицы и поля запросов, ЗНАЧЕНИЕ(…) — на то, чего нет |
| свойства_формы | переменная с именем свойства формы (`Доступность = …`) |
| вложенность_форм | таблица в таблице, страница вне набора страниц — клиент падает с ошибкой XDTO |
| дерево_форм | элемент лежит прямо в группе, а не в `<ChildItems>` — платформа его выбрасывает |
| дубли_формы | два поля ввода на один реквизит, одна команда двумя кнопками, пустые группы, поле без данных |
| иконки | кнопка своей команды без картинки, картинка без Representation, голая вкладка среди одетых, общая команда/подсистема без картинки, HeaderPicture вне таблицы, битая ссылка CommonPicture.УЗ_ |
| компоновка_форм | надпись вместо подписи, цвет числом, таблица короче 7 строк, ширина у ссылки, высота без предела, две командные панели, ряд шире 1280 px |
| обработчики | событие указывает на несуществующую процедуру; процедура события формы или ПОЛЯ написана и не подключена; два блока Events; чужой обработчик при своём |
| печать | параметр табличного макета, который никто не заполняет; параметр на текстовом формате; макет, который никто не получает |
| повторы_тегов | одно свойство дважды в XML — платформа молча берёт последнее |
| скрипты | эта опись: диск ↔ АУДИТЫ ↔ docs/проверки.md, тесты запускаемы, пути в docs живые, докстроки, компиляция |
| честность_проверок | немой тест, проглоченная ошибка, `проверить(True)`, проверки под «если нашлись» без else; две копии логики в форме и модуле объекта |
| чужие_коллекции | ЦветаСтиля/ШрифтыСтиля/БиблиотекаКартинок.X, где X — элемент конфигурации хозяина (по выгрузкам хозяев) |
| элементы_форм | `Элементы.X` в модуле формы, а элемента X на форме нет |
| начальная_страница | расширение объявляет или пишет начальную страницу хозяина |
| автозаполнение | пустой обработчик ПриИзменении; подстановка только в пустое поле без вопроса |
| bom | .bsl/.xml без метки UTF-8 |
| вёрстка_панелей | надписи, группы, поля внутри командной панели — веб-клиент рвёт соединение |
| форматы_чисел | «ЧГ=3 0» (не разбирается), формат в HTML без «ЧН=» |
| сетка_форм | в вертикальной группе поля начинаются вразнобой (> 26 px) |
| ширина_заголовков | заголовок колонки-флажка шире её Width, значок в шапке флажка |
| комментарий_последним | «Комментарий» не последний реквизит объекта / элемент группы формы |
| малые_иконки | своя картинка режется по краю, мелкая, пустая или сплошное пятно |
| права_роли | у своего объекта нет рабочего набора прав в УЗ_ОсновнаяРоль; права у секрета УЗ_НастройкиПочты; InteractiveDelete |
| совместимость_метаданных | с эталона выпуска (`tools/аудиты/эталон_метаданных.json`) удалён/переименован объект или реквизит, сменён тип — без записи о миграции; `--принять` при выпуске |
| сверка_хозяев | заимствованные объекты, поля Организаций/Пользователей в запросах и ЗначениеРеквизита, методы БСП из УЗ_Среда — есть в выгрузках УНФ 3.0.12, БП, УТ 11.5 |

## COM-тесты (tools/тесты, запускатель прогон.py, формат сеанс.py)

| Тест | Что проверяет |
|---|---|
| тест_аудит_данных | инварианты данных: проведённый документ имеет движения; регистратор движений жив и проведён; нет ссылок на удалённые объекты в регистрах, документах, справочниках УЗ (самопроверка в транзакции с откатом). Идёт последним. Псевдонимы `УЗИсточник/УЗЦель` — у документов хозяина есть реквизит «Цель» (УТ: ЗаявкаНаКомандировку), с псевдонимом `Цель` запрос падал «Неоднозначное поле» |
| тест_даты_запрета | запрет изменения по датам (УЗ_ДатыЗапрета) |
| тест_обновление | обработчики обновления данных (УЗ_ОбновлениеДанных, УЗ_ВерсииДанных) |
| тест_оповещения | напоминания и оповещения (УЗ_Оповещения); долг 1 234,56 — точная строка «Задолженность УЗ тест оповещений Сидорова Анна: 1 234,56» и «задолженность 1 234,56 руб.» в письме (было `"1" in Описание`); регистратор-«призрак» долга постоянный — после обрыва снимается следующим прогоном |
| тест_отчеты | все отчёты на СКД формируются, поля с заголовками; **цифры на своих данных** (ПКО 1 234,56, урок 1 000): УЗ_ВедомостьПоКассе — строка ПКО; три отчёта со своей формой выполняются серверным кодом модуля формы на стенде (`tools/тесты/стенд_форм.py`: модуль формы → внешняя обработка, кэш по хэшу) — УЗ_ВедомостьПоКассеДляМенеджеров, УЗ_АналитикаПоУченикам (оплата и урок в строке предмета), УЗ_ДвиженияДокумента по ПКО. Было `проверить(True)` и «высота > 0» |
| тест_печать | ПКО/РКО и начисление бонусов: своя печать и через БСП хозяина; отказ «чужого менеджера» — по причине «неизвестный менеджер печати» |
| тест_права | живой сеанс сотрудника с УЗ_ОсновнаяРоль: всё нужное можно, секреты нельзя; отчёт сотрудника — приход 8 000 в строке его ПКО (было «высота > 0») |
| тест_урок | цена тарифа при проведении урока (отказ засчитывается только с сообщением «нет цены» у поля Ученики[0].Тариф), новый педагог в группе «Педагоги» |
| тест_фото | фото физ. лиц |
