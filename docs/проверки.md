# Опись проверок «Учёта занятий» (УЗ_ext)

Опись сверяет сам аудит `скрипты` (`tools/аудиты/скрипты.py`): каждый аудит и каждый COM-тест
на диске обязан быть назван здесь, каждый путь `tools/…/*.py` в `docs/*.md` — существовать.
Добавил проверку — допиши строку сюда, иначе все_аудиты покраснеет.

## Как запускать

    pwsh -File tools\финал.ps1 -База C:\1c_bases\UZ_BP_E [-Сценарии] [-БезДеплоя]  # ФИНАЛ одной командой: аудиты → деплой → прогон → сценарии, один итог; код 1 на первом красном (проверено: база не найдена → красный на деплое; src_ext изменён после деплоя → красный на прогоне)
    python tools/итерация.py --база=C:\1c_bases\UZ_BP_C   # ИТЕРАЦИЯ: правка src_ext → в базе → затронутые тесты (~10–11 с)
    python tools/итерация.py --база=C:\1c_bases\UZ_BP_C --тест=касса --модули   # свой тест + /CheckModules
    python tools/итерация.py --база=C:\1c_bases\UZ_BP_C --стоп                  # остановить сервер итераций базы
    python tools/сверка_выгрузки.py %TEMP%\uz_agent\UZ_BP_C\dump               # дошла ли загрузка: выгрузка ↔ src_ext
    python tools/аудиты/все_аудиты.py              # все офлайн-аудиты src_ext, бюджет ≤ 5 с (печатается)
    python tools/аудиты/самотест.py                # каждая проверка обязана краснеть: мутации на фикстурах
    python tools/прогон.py                         # ПОЛНЫЙ: все COM-тесты на УНФ, БП, УТ (с двойниками UZ_*_2) — граница этапа
    python tools/прогон.py --быстро                # РАБОЧИЙ ЦИКЛ: только тесты, затронутые изменениями с зелёного полного
    python tools/выбор_тестов.py --изменено=src_ext/AccumulationRegisters/УЗ_Касса.xml   # что выберет --быстро и почему
    pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_UNF_A -БезСборки -Прогон Быстрый   # деплой + быстрый прогон
    python tools/прогон.py --без-двойников         # каждая база одним процессом (дольше; для сравнения)
    pwsh -File tools\агенты.ps1                    # процессы 1cv8: свои агенты (простой, сторож) и чужие
    pwsh -File tools\агенты.ps1 -Остановить -Все   # остановить свои агенты (или -База УНФ | UZ_UNF_K | C:\1c_bases\…)
    python tools/прогон.py --база=C:\1c_bases\UZ_UNF_B --пользователь=Администратор --тест=аудит_данных
    pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_UNF_D          # загрузка расширения в свою копию
    pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_UNF_D -НесмотряНаАудит   # осознанно при красном аудите (с 28.09 аудиты 0)
    python tools/убрать_сирот.py --база=C:\1c_bases\UZ_UNF_D            # сироты в регистрах УЗ_: отчёт
    python tools/убрать_сирот.py --база=C:\1c_bases\UZ_UNF_D --исправить  # …и уборка
    python tools/мутации_проверок.py --база=C:\1c_bases\UZ_UNF_D        # COM-проверки краснеют (8 мутаций, ~3 мин)
    pwsh -File tools\мутации_гейта.ps1 -База C:\1c_bases\UZ_UNF_D       # гейты деплоя краснеют (~2 мин)

## Две платформы: 8.3 и 8.5 (tools/платформа.py, 30.09.2026)

Разработка ведётся на обеих линиях платформы. Путь к платформе, версия, COM-класс и модуль веб-сервера берутся
**только** из `tools\платформа.py` (раньше `8.3.27.1936`, `V83.COMConnector`, `wsap24.dll` были зашиты в 13 файлах tools).
- Выбор линии: `--платформа=8.3|8.5` у любого python-инструмента, `-Платформа 8.3|8.5` у `деплой.ps1` и `финал.ps1`,
  либо переменная среды `UZ_ПЛАТФОРМА`; по умолчанию 8.3. Версия — самая новая установленная сборка линии в
  `C:\Program Files\1cv8` (сейчас 8.3.27.1936). Линии нет — «платформа 8.5 не установлена: C:\Program Files\1cv8\8.5.*», код 1.
- COM-класс не угадывается: 8.3 — `V83.COMConnector`; 8.5 — `V85.COMConnector`, если он есть в реестре, иначе
  `V83.COMConnector`, но только если он зарегистрирован на каталог 8.5; иначе ошибка с подсказкой `regsvr32 …\comcntr.dll`.
- Две команды: `pwsh -File tools\финал.ps1 -База C:\1c_bases\UZ_BP_Q` (8.3) и
  `pwsh -File tools\финал.ps1 -База C:\1c_bases\UZ_BP_Q85 -Платформа 8.5`. Итог печатает платформу и сборку.
- **Базы — отдельные копии.** Файловая база, открытая более новой платформой, может перестать открываться старой, поэтому
  песочница 8.5 — своя копия с суффиксом `85` (`C:\1c_bases\UZ_BP_Q85`), общих баз у двух линий нет. Копию делать с 8.3-базы,
  не открывавшейся 8.5.
- **Метка платформы** — файл `.платформа` («8.3» или «8.5») в папке базы. Ставит первый деплой (`деплой.ps1` →
  `платформа.py --метка=<база>`); деплой, итерация, прогон и агент конфигуратора другой линией отказывают с пояснением.
  База без метки: деплой на 8.3 метку ставит; на 8.5 — только если имя базы кончается на `85` (иначе это база 8.3, отказ).
  Серверные базы метки не имеют. Ручная проверка: `python tools\платформа.py --проверить=<база> --платформа=8.5`.
- **Веб-обход форм и снимки делать на обеих линиях** (`tools\видео\стенд.py`, `--платформа=8.5`): интерфейс 8.5 отличается,
  правка формы, зелёная на 8.3, на 8.5 может выглядеть иначе. Перед выпуском — прогон на обеих.
- Пока 8.5 на стенде не установлена, `--платформа=8.5` даёт только понятную ошибку; проверено: `python tools\платформа.py --платформа=8.5` → код 1.

## Деплой (tools/деплой.ps1): гейты и время

Порядок: офлайн-проверки параллельно (проверка src_ext, все аудиты, самотест аудитов — самотест только если
`tools/аудиты` изменились с последнего зелёного: кэш по отпечатку содержимого) → **красное — СТОП до загрузки**
(исключение — ключ `-НесмотряНаАудит`, печатается ПРЕДУПРЕЖДЕНИЕ) → на каждую базу: сервер итераций базы
останавливается (он держит агента и COM-сеанс) → замок → загрузка → **загрузка дошла** (выгрузка ↔ исходники) →
`/CheckModules` (до применения) → применение → отметка деплоя. Если файлов не менялось, но в базу грузила
итерация (отпечаток помечен `"итерация": true` — она /CheckModules не гоняет), деплой гоняет `/CheckModules` сам.

| Что | Как устроено |
|---|---|
| разбор результата | не по словам. Пакетная загрузка/применение — зелёные, только если код 0 **и журнал /Out пуст** (при успехе платформа молчит, любой текст печатается целиком). `/CheckModules` — код 0, «Синтаксических ошибок не обнаружено» и ни одной строки `{Модуль(стр,кол)}:`. Агент — строка ответа вида `Ошибка ConfigFilesError - …` |
| загрузка дошла (28.09.2026) | агент и пакетный конфигуратор на части ошибок XML отвечают «успешно» и МОЛЧА выбрасывают загружаемое (картинка команды на несуществующую `CommonPicture` → `<xr:Ref>0</xr:Ref>`; свойство, которого у реквизита ТЧ нет, — `<Indexing>`), а на `load-files` после `update-db-cfg` агент отвечает «Ошибка UnknownError» — без « - текст», старый разбор считал это успехом (дыра: `/CheckModules` проверял старый код, отметка писала новый отпечаток; разбор исправлен). После загрузки агент выгружает конфигурацию (`config dump-files --update`, пакетно — `/DumpConfigToFiles -update`) в `%TEMP%\uz_agent\<база>\dump`, `tools/сверка_выгрузки.py` сравнивает её с исходниками: .bsl — текстом, XML — вложением значений (каждое значение исходника есть в выгрузке), справка — без пробелов. Известное — `tools/сверка_выгрузки_линия.json` (5 файлов: `<Width>`/`<Header>` колонок форм УЗ_Урок, `AutoInsertNewRow`, `AutoSaveDataInSettings`; `<Client>false` общих модулей — свойства нет в формате 8.3 — с 29.09.2026 убран из src_ext и конвертера: его нашёл аудит схема_платформы), новое — красное, в базу не применяется. **Расхождение после загрузки агентом** (29.09.2026) — не сразу стоп: агент останавливается, идёт **пакетная полная загрузка с /Out** — только она называет причину («Исключение XDTO … Form.xml», «Неверное свойство объекта метаданных»); красная — её журнал печатается, в базу не применено; зелёная — сверка ещё раз пакетной выгрузкой (строки «загрузка дошла (агент)», «загрузка (пакетно, причина)», «загрузка дошла (пакетно)»). Находка сверки при слиянии «Перевода ученика»: `УЗ_СоставГрупп` — `MainFilterOnPeriod=true` у регистра, подчинённого регистратору, конфигуратор молча ставил false; в src_ext исправлено на false |
| применение пакетно | зелёное при коде 0, если каждая строка журнала — сообщение платформы («Новый объект: …», «Объект изменен: …», «Регистрация изменена: …», «Реорганизация…», «Обработка структуры…», «Принятие изменений…», «Создано поколение…»); раньше любой текст краснел — ложно на новых объектах. Формы строк — из настоящих журналов 8.3.27 (UZ_BP_E 28.09: «Новый объект: Документ.УЗ_ПереводУченика», «Объект изменен: ЖурналДокументов.УЗ_ОбщийЖурнал»); «Объект изменен» до 29.09.2026 не узнавался — краснел. модулей ОШИБКА», в базу не применено; тип реквизита на несуществующий справочник в XML — «загрузка ОШИБКА»

на мутацию с возвратом базы): «Проба = ;» — проверка модулей красная; тип на несуществующий справочник — пакетная

схема_платформы); **обратная проверка** — новый реквизит документа, `-БезАгента`: журнал применения «Объект изменен: …»,

больше не доступен» (лицензии заняты соседями), пакетное применение с тремя «Объект изменен: …» — зелёное.

## Итерация (tools/итерация.py): правка → в базе → затронутый тест

Требование владельца (28.09.2026): одна итерация разработки — не более 10 с. Деплой (60 с) и полный прогон — только

## Прогон (tools/прогон.py)

### Два режима: быстрый — рабочий цикл, полный — граница этапа (28.09.2026)

| Режим | Что идёт | Бюджет | Когда |
|---|---|---|---|
| `--быстро` | «расширение» (сверка src_ext с базой) + тесты, затронутые изменениями src_ext/tools с прошлого ЗЕЛЁНОГО ПОЛНОГО прогона этой базы + «запросы» (если менялся src_ext) + аудит_данных последним | 30 с | после каждого деплоя (`деплой.ps1 -Прогон Быстрый`) |
| полный (без ключа) | все тесты (55 тестов + «расширение» + «запросы» на базу; три базы × основная+двойник) | 120 с | граница этапа, перед слиянием/выпуском |

Зелёный полный прогон пишет снимок `%TEMP%\уз_прогон\зелёный_полный.json` (sha1 каждого файла src_ext/** и tools/**,
CRLF = LF) для каждой базы прогона — точку отсчёта быстрых. Нет снимка базы — быстрый берёт все тесты (печатается)
и, если зелёный, сам пишет снимок. Быстрый прогон снимок не двигает: изменения копятся до следующего полного.

Выбор — `tools/выбор_тестов.py` (его же зовёт прогон; отдельно — `--изменено=путь,путь`, `--карта`):
* карта «тест → объекты src_ext» — имена объектов src_ext (имя файла/папки вида) словом целиком в СОБСТВЕННОМ тексте
  теста (`УЗ_Касса` не совпадает с `УЗ_Кассы` и `УЗ_КассовыйЖурнал`) + явная метка `# затрагивает: А, Б` (подписки
  на события, песочница почты, дисконтные карты, календарь, регистр уроков в расчётах — там, где имени в тексте нет);
* объекты helper-ов (`_деньги`, `фабрика`…) тестам не приписываются, иначе правка регистра, который helper
  заполняет попутно, тянула бы полсотни тестов; правка самого helper-а выбирает все импортирующие его тесты
  (транзитивно); `сеанс.py`, `прогон.py`, `выбор_тестов.py`, `отпечаток_src.py` — все тесты (изменилась обвязка);
  `проверка_запросов.py` — «запросы»; аудиты, деплой, нагрузка — COM-тестов не касаются;
* изменённый файл без теста печатается строкой «без тестов» (клиентские модули, картинки, модуль приложения —
  COM их не проверяет; Configuration.xml — версию и состав сверяет «расширение»).
Прогон печатает каждый выбранный тест с причиной («УЗ_Касса (имя в тексте теста: src_ext/…/УЗ_Касса.xml)»).

### Скорость: двойники баз, P-ядра, предел лицензий (28.09.2026)

Разложение по тестам (журнал прогона, поле «полное» в `%TEMP%\уз_прогон\УНФ.json` — с подключениями сотрудников
и контролем сирот): УНФ одним процессом ≈ 63–69 с = подключение 7–8 + работа ≈ 56–62, из неё тест_права ≈ 19–25 с

первый отчёт СКД в сеансе каждого сотрудника ~4), тест_отчеты 5–7 (первый СКД сеанса), остальные 27 тестов ≤ 3,5 с.

## COM-тесты (tools/тесты, запускатель прогон.py, формат сеанс.py)

**Время тестов не зависит от времени суток (29.09.2026).** Прогон в 00:03 дал провалы: уроки «сегодня в 0:04–0:06»
ещё не начались («раньше начала провести нельзя»), ПКО кассы К6 «сегодня в 0:05» ещё в будущем (остаток 0); прогон
утром ломал бы ПКО фабрики «сегодня в 9:00», вечером у полуночи — переход суток посреди прогона. Теперь каждый
COM-сеанс тестов (`сеанс.подключить`, сеанс сотрудника `т.подключить`, итерация) получает пояс `Etc/GMT±N`, в котором
«сейчас» — около 12:00 ДНЯ ТЕСТОВ (реального сегодня на момент первого подключения процесса): `сеанс.закрепить_время`.
«Сегодня до 10:00» — всегда прошлое (урок проводится, ПКО в остатке), «сегодня после 14:00» — будущее (план).
Даты в тестах — от `сеанс.сегодня()` / `сеанс.сейчас()` (фабрика — `ф.сегодня`, `ф.день`), не от
`datetime.date.today()/now()`. Фоновые задания идут в поясе базы — их «сегодня» реальное (тест_права принимает оба).
Проверка подменой: `UZ_ЧАС_ТЕСТОВ=0` — сеансы в 00:ММ (минуты реальные: в 01:03 компьютера сеанс — 00:03),
`UZ_ВРЕМЯ_КАК_ЕСТЬ=1` — без закрепления (как было).

## Сценарии пользователей по ролям (tools/сценарии, тест-менеджер 1С)

Настоящий тонкий клиент под пользователем роли (руководитель, менеджер, педагог) и штатный тест-менеджер платформы:
открывает формы по навигационным ссылкам, заполняет поля, жмёт кнопки, проверяет значения, видимость и отказы прав.
Сценарии — данными (`tools\сценарии\сценарии.json`), исполнитель общий (`УЗ_Сценарии`). Запуск и формат шагов —
`tools\сценарии\README.md`:

    python tools\сценарии\прогон_сценариев.py                 (UZ_BP_C, три роли, ~90–100 с, бюджет 120 с)
    python tools\сценарии\прогон_сценариев.py --самопроверка  (6 ложных шагов — все обязаны покраснеть)

Что покрыто (28.09.2026, UZ_BP_C, все зелёные, 101 шаг): **руководитель** — помощник первого запуска (7 шагов) и
«Создать уроки на неделю» → «Выполнить»; провести сегодняшний урок (все пришли, оплачены, тема, ДЗ, сумма 700);
приход денег по задолженности (700); расчёт зарплаты (период по умолчанию, «Заполнить и рассчитать» = 517, провести);
«Пользователь программы» в карточке педагога. **Менеджер** — урок открывается без ошибок, ставка и страница
«Начисления педагогу» скрыты; оплата ученика; отказ: расчёт зарплаты (форма и список), полная ведомость по кассе,
дополнительные расходы. Не реализовано (помечено в сценарии с причиной): менеджер создаёт новый урок группы.
**Педагог** — «Мои уроки»: связь с карточкой, свой урок, «Все пришли», тема и ДЗ записаны (проверено после
«Обновить»); «Моя зарплата» — начислено 517; отказ: чужой урок по ссылке, приходы денег, список всех уроков.
После прогона — журнал регистрации: ошибок применения расширения при входе сотрудников быть не должно.

Время суток (29.09.2026): сегодняшний урок помощника — в 0:01 (`{время}`, заголовок формы «Урок*от {сегодня_кратко}
({время})», день без ведущего нуля, как в представлении урока `д.ММ.гг`); с 23:50 до 00:02 прогон ждёт 00:02
(`дождаться_дня`): клиенту роли время не закрепить, как COM-сеансу, — пояс базы меняется только монопольно.

Чему можно верить: `--самопроверка` — неверное ожидаемое значение, несуществующая кнопка, «отказ» там, где права

`Новый Файл(П).Существует()` и `Процедура ВвестиЗначение` — оба красные.
