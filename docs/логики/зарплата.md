# Логика: зарплата педагогов

Разбор 28.09.2026, только чтение кода `src_ext`. Пути ниже — от `src_ext\`. Решения владельца — [аудит_полный_2026-09-28.md](../аудит_полный_2026-09-28.md), раздел 7 (В6, В7, В9, В13).

## 1. Назначение

Владелец студии задаёт педагогу условие оплаты (ставку): «за занятие», «за час», «с человека» или «% с оплаты ученика».
Каждый проведённый урок сам начисляет педагогу деньги по ставке, руководитель может дописать доплату. Разовые суммы
(премия, замена) — документом «Начисления педагогам». Всё начисленное — **долг студии педагогу**. Раз в период
руководитель делает **расчёт зарплаты** (ведомость: какие уроки и начисления оплачиваем) и на его основании выдаёт
деньги **РКО «Выплата зарплаты»**, которое гасит долг.

## 3. Где реализовано — «место × как считает»

**Начисление педагогу за урок**

| Место | Как считает |
|---|---|
| Запись урока (сервер) `ObjectModule.bsl:33` | полный пересчёт по ставке, явкам, оплатам |
| Форма урока — смена часов, группы, «К оплате», скидки, кнопки «Сделать посещёнными/оплаченными», «Пересчитать начисления» | тот же `ПересчитатьНачисленияПедагога` |
| Форма урока — отметка **одной** «Явки» | **не пересчитывает** (у колонки `Ученики.Явка` нет OnChange, `Form.xml:953`) — на экране старая сумма до записи |
| Форма урока — смена педагога | чистит все строки, включая ручные (`Form\Module.bsl:543`) |
| Урок из панели/помощника/календаря | ставка карточки педагога (B07) и пересчёт при записи |
| Справка ставок `Catalogs\УЗ_СтавкиПедагогов\Ext\Help\ru.html` | «срок действия **не проверяется**» — **неверно**, код проверяет (правило 4) |

**Долг педагогу — где виден и одинаково ли**

| Место | Что показывает | Совпадает с остатком `Сумма`? |
|---|---|---|
| Отчёт «Расчеты по зарплате» (`Reports\УЗ_РасчетыПоЗарплате\…\Template.xml:177-241`) | «Начислено» (СуммаПриход), «Оплачено» (СуммаРасход), «Остаток к оплате» (СуммаКонечныйОстаток), «Сумма урока», «Выручка» = сумма урока − начисление | да — это и есть долг; поле «Остаток по расчётам зарплаты» (`ЗПКонечныйОстаток`) доступно, но всегда 0 |
| Форма расчёта (`Form\Module.bsl:184-210`) | «ВЫПЛАЧЕНО / НЕ ПОЛНОСТЬЮ / ПЕРЕПЛАЧЕНО / НЕ ВЫПЛАЧЕНО» по сравнению `СуммаДокумента` с суммой **одного** РКО из `Объект.РКО` | нет: только по этой ведомости и только по одному РКО; второй (частичный) РКО и РКО, введённый через «Создать на основании», не учитываются |
| Журнал `DocumentJournals\УЗ_ОбщийЖурнал.xml:238-277` | колонка «Сумма»: у урока — выручка урока (`Сумма`), у расчёта — к выплате, у РКО — выдано, у разового начисления — сумма | долга нет вовсе; в колонке «ФизЛицо» нет `УЗ_НачисленияПедагогам.Педагог` — отбор журнала по педагогу разовые начисления не покажет |
| Карточка педагога `Catalogs\УЗ_ФизЛица\…\Form\Module.bsl:350` | ветка `Если Объект.ЭтоПедагог Тогда` пустая | долг педагогу не показан |
| РКО на основании (`УЗ_РасходДенег\Ext\ObjectModule.bsl:238`) | сумма = расчёт − выплачено по расчёту | остаток ведомости, а не долг |

Итого три разных «долга»: остаток регистра (всё начисленное, в т.ч. ещё не вошедшее в ведомость), остаток ведомости (РКО) и статус формы (один РКО).

## 4. Расхождения и следы трёх режимов

1. **Изменение урока после расчёта не защищено.** Урок, вошедший в проведённый (и даже оплаченный) расчёт, можно перепровести с другой суммой, отменить или удалить — проверок в уроке нет (защищён только сам расчёт, N01, и дата запрета). Последствия: долг в регистре меняется, а ведомость — нет; разница **никогда** не попадёт в новый расчёт, потому что документ целиком исключён (правило 20). Урок отменён после выплаты → остаток `Сумма` уходит в минус (переплата), ведомость не знает. Противоречит В9 («фиксация вошедших уроков»).
2. **`КОплате` < `Начисление`** — недоплаченная разница остаётся в долге регистра, но урок исключён из будущих расчётов → выплатить её через расчёт нельзя (а без расчёта выплата запрещена, В9). Долг «зависает».
3. **Смена педагога в форме урока стирает ручные доплаты** (правило 13), хотя пересчёт по ставке их бережёт (B06) — два поведения одной ТЧ.
4. **Справка ставок противоречит коду** о сроке действия (раздел 3).
5. **«Один способ в ставке» — только клиентская форма**; сервер молча берёт первый по приоритету.
6. **«% с оплаты» — от суммы после скидки, без вычета доп. расходов (материалов)** и с оплаченными неявками. Отчётная «Выручка» (`Template.xml:227-236`) = сумма урока − начисление, тоже без доп. расходов урока.
7. **Статус формы расчёта** считает один РКО (раздел 3) — при частичной выплате двумя РКО пишет «НЕ ПОЛНОСТЬЮ» навсегда; при РКО «на основании» — «НЕ ВЫПЛАЧЕНО».
8. **`ЗП` — ресурс-пустышка для остатков** (правило 18): в отчёте «Остаток по расчётам зарплаты» всегда 0.
9. Старые выплаты из обновления (правило 27) — без расчёта в основании: перепроведение такого РКО теперь откажет (правило 25).
10. **Три режима продукта**:
    - *Рок-школа* (индивидуально, почасово): «за час» — от часов **урока**, а не ученика; для индивидуального урока это верно. Неявка единственного ученика → 0 (В6), даже если урок оплачен («К оплате» неявки, В3) — ученик платит, педагог не получает.
    - *Школа математики* (группы, поурочно, абонементы): «за занятие» — одна ставка на группу при ≥1 явке; «с человека» — по явкам; «%» — от цен строк, у абонемента — цена/число занятий (В2). Работает.
    - *Школа робототехники* (группы, наборы, доп. расходы): расходы на материалы идут в `УЗ_Расходы`, но «%» педагога и «Выручка» отчёта их не учитывают — педагог получает % и с денег, ушедших на наборы.
    - Общий след: **одна ставка на педагога** (карточка), у группы ставки нет. Педагог, ведущий и индивидуальные (за час), и группы (с человека), получит в групповом уроке ставку карточки; правильную надо выбирать руками в каждом уроке (и при смене группы в форме её перетрёт ставка карточки, `Form\Module.bsl:437`).

## 6. Вопросы владельцу

«Как в типовых» решается всё, кроме одного:

- **«% с оплаты» у робототехники:** считать от суммы урока или от суммы **за вычетом доп. расходов** (наборы, материалы)? В типовых (УНФ) процент берётся от выручки без вычета затрат, поэтому по умолчанию оставляем как есть — нужен ответ, только если владелец хочет «от маржи».
