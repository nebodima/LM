# Логика: оповещения и почта

Разбор 28.09.2026 по исходникам `src_ext` (расширение УЗ_ext) и исходной конфигурации LM (корень проекта). Код и база не менялись.
Пути ниже — от `src_ext\`, если не сказано иное; LM-файлы — от корня проекта.

## 1. Назначение

Владельцу студии нужно три вещи:
1. **Не прозевать должника.** Раз в день программа сама находит учеников, которые давно «в минусе», и показывает всем сотрудникам всплывающее оповещение «Задолженность Иванов Пётр: 1 500,00»; при включённой почте — пишет ученику/родителю письмо.
2. **Напомнить себе** о деле по уроку, ученику, оплате: кнопка «Напомнить» → через час (или в выбранное время) всплывёт окно.
3. **Поздравить именинника.** В журнале уроков — список дней рождения на сегодня и ближайшие 10 дней.

Замена «Напоминаний пользователя» и «Почты» БСП: у расширения свой регистр `УЗ_Оповещения`, свой таймер и своя отправка через `ИнтернетПочта` — работает в хозяине без БСП (УНФ, БП, УТ одинаково).

## 4. Расхождения

1. **В12 нарушено в задании о долге** (`УЗ_Сервер:86–97,101–117`). Остаток сворачивается по организациям: аванс в А гасит долг в Б, а долг в А «растворяется» в переплате по Б. Письмо не называет организацию (`УЗ_Почта:245–250`). Так же — диаграмма журнала уроков (`ФормаСписка\...\Module.bsl:172–187`). Панель ученика и документы уже по организации — числа расходятся.
2. **Педагог-ученик**: диаграмма исключает `ЭтоПедагог` (`:178`), задание — нет: педагог с минусом получает оповещение и письмо, в диаграмме его нет.
3. **Срок N дней по двум точкам** (N06 из `docs\аудит_codex_повтор_2026-09-28.md:205`): погашение между точками не видно — новый долг оповещается сразу.
4. **Сумма в оповещении «замерзает»**: пока оповещение не завершено, новое не заводится (`:132–140`) — долг вырос с 1 000 до 3 000, в окне по-прежнему 1 000. Погашенный долг оповещение **не закрывает** — висит «Задолженность … 1 000,00» у всех, хотя ученик оплатил.
5. **Письмо не повторяется при сбое SMTP** (Q07): запись оповещения уже есть (`:157`), письмо упало (`:175–178`) — до ручного «Завершить» письма не будет. И наоборот: после «Завершить» при живом долге завтра — новое письмо (каждое «Завершить» = ещё одно письмо должнику).
6. **Гонка задание × таймер**: `СрокНапоминания = Сейчас` фиксируется в начале задания (`:145,154`), а записи пишутся по одной с письмом между ними (таймаут SMTP 30 с, `УЗ_Почта:94`). Клиент, проверивший регистр в эти секунды/минуты, сдвигает `ПоказаныДо` дальше — записи, закоммиченные позже, **в этом сеансе не всплывут никогда** (только после перезахода).
7. **Анти-дубль по тексту** (`ПОДОБНО "Задолженность%"`): ручное общее напоминание руководителя с текстом «Задолженность …» по ученику блокирует автоматику; смена `НСтр` при переводе ломает поиск своих записей.
8. **Права в обход API**: сервер проверяет чужие ключи (`УЗ_Сервер:273–275,302–304`, тест_права), но у менеджера право «Изменение» регистра без RLS (`Rights.xml:1664`), а в форме записи `Пользователь`/`Завершено` редактируются — через стандартную форму менеджер ставит напоминание руководителю или завершает чужое. `ВремяСобытия` в форме — часы клиента (`ФормаЗаписи\...\Module.bsl:6`), в API — `ТекущаяДатаСеанса`.
9. **Период по умолчанию разный**: сервер 60 с (`УЗ_Сервер:186`), обновление и форма настроек — 300 с (`УЗ_ОбновлениеДанных:168`, форма `:48`), LM — 300. Менеджеру без записи настроек достанется 300 (он читает `УЗ_Настройки`), а без права чтения — 60.
10. **Таймер не зависит от «Использовать оповещения»** (`УЗ_Сервер:184–199`), в LM зависел (корень `Ext\ManagedApplicationModule.bsl:45–48`). Осознанно (ручные напоминания), но флажок в настройках называется так, будто выключает всё.
11. **Счётчик «Оповещений: 20»** при 57 наступивших (`ПЕРВЫЕ 20`, `УЗ_Сервер:220,249`).
12. **Пароль SMTP — открытым текстом** в ресурсе регистра (`УЗ_НастройкиПочты.xml:470–481`); в типовых — безопасное хранилище (`ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище`). Защита сейчас только отсутствием прав у ролей УЗ; выгрузка в .dt/копия базы/обработка с «Полными правами» его видят.
13. **Безопасный режим**: задание, настройки и почта читают через `УстановитьПривилегированныйРежим` (`УЗ_Настройки\Ext\ManagerModule.bsl:11`, `УЗ_Почта:20,82`) до обработки ошибок; в безопасном режиме (по умолчанию для расширения из файла) письмо/задание может падать исключением после первой записи — K02 `docs\аудит_codex_повтор_2026-09-28.md:106`, фактическое поведение фонового задания [?] не проверено.
14. **Дни рождения**: колонка «Возраст» устаревшая (хранимая); в список попадают педагоги и родители (возможно, желательно — но без пометки «кто»); «Родитель2» нет вообще — письмо уходит только Родитель1.
