# Разбор логик по отдельности

Продукт дорабатывался поэтапно: сначала под рок-школу владельца, потом под школу математики, затем под школу робототехники. Фитнес-клубы — не наша аудитория (у 1С свой продукт). Поэтому каждая
бизнес-логика проверяется отдельно и целиком — во всех местах кода, где она реализована.

Логика состава групп и перевода ученика (В29) — `группы_состав.md`.

Напоминания и каналы сообщений — почта, Telegram, SMS, WhatsApp (этап 2.2, В45–В52) — `напоминания.md`.

Шаблон документа логики (docs/логики/<логика>.md):
1. **Назначение** — что это для владельца студии, простыми словами.
2. **Правила как есть** — нумерованный список правил, каждое с `файл:строка`, где оно реализовано.
3. **Где реализовано** — все места (документы, формы, обработки, отчёты, общие модули, регламентные): одно правило в N местах — таблица «место × как считает».
4. **Расхождения** — где одно и то же считается по-разному; следы трёх режимов — «рок-школа» (индивидуальные, почасовые), «школа математики» (группы, поурочно, месячные абонементы), «школа робототехники» (группы, наборы/материалы, доп. расходы) — что работает только для одного режима — что работает только для одного режима.
5. **Сценарии с числами** — 5–15 сценариев «дано → действие → ожидаемый результат в регистрах/формах», включая граничные; помечены, какие уже покрыты тестами tools\тесты (файл), а какие нет.
6. **Вопросы владельцу** — только если правило нельзя решить «как в типовых» (решения уже принятые — docs/аудит_полный_2026-09-28.md раздел 7, В1–В14).
7. **Предложения по исправлению** — с файлом:строкой.
