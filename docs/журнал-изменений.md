# Журнал изменений «Учёта занятий»

Что вошло в каждую версию расширения `УЗ_ext`. Детали — в `git log` ветки `uz-ext` и в отчётах `docs/аудит_*.md`.

**Правило:** подняли `<Version>` в `src_ext/Configuration.xml` — дописали сюда блок `## <версия> — <что> (<дата>)`
и положили собранный `.cfe` в `releases/` (`releases/README.md`). Аудит `журнал_изменений` сверяет: версия из
`Configuration.xml` обязана быть заголовком блока здесь, иначе все_аудиты красные и деплой не стартует.
Формулировки — для покупателя: что изменилось у него, а не какие модули правились.

## 2.1.0.1 — плательщики ученика и один платёж за нескольких учеников (29 сентября 2026)

- **Несколько плательщиков у ученика.** В карточке ученика — страница «Плательщики»: мама, папа, бабушка («Кем
  приходится»), один из них основной. Основной подставляется в приход денег; на главной странице карточки — поле
  «Основной плательщик». Прежнее поле «Родитель (родств.)» при обновлении переносится в основного плательщика.
- **Плательщик в каждой оплате.** В приходе денег поле «Плательщик» (вместо «Отв. лицо ученика») — кто внёс деньги;
  пустое — платит сам ученик. В приходном кассовом ордере «Принято от» — плательщик.
- **Один платёж за нескольких учеников.** «Несколько учеников» в приходе денег — расшифровка платежа: ученик,
  предмет, абонемент, сумма; сумма документа — итог строк, деньги засчитываются каждому ученику. «Заполнить по
  долгам» — все ученики плательщика с их долгами. За одного ученика приход заполняется как раньше.
- **Отчёт «Оплаты по плательщикам»:** кто сколько внёс за кого за год — внесено, возвращено, итог по организации,
  плательщику и ученику. Основа справки об оплате обучения для налогового вычета (сама справка — в следующей
  версии).
- **Возврат — тому, кто платил.** В расходе денег при возврате ученику поле «Получатель»: по умолчанию плательщик
  последней оплаты по предмету; в ордере «Выдать» — получатель. Возврат уменьшает внесённое им в отчёте.
- Письма о задолженности уходят ученику и всем его плательщикам с отметкой «Оповестить по email».
- Обновление данных (шаг 2): прежний «Родитель (родств.)» → основной плательщик; приходы и возвраты 2.0 получают
  плательщика (приход — «Отв. лицо ученика», если было указано, иначе сам ученик; возврат — кто платил до него).
  Суммы, остатки и проводки не меняются. Первым после обновления журнал уроков открывает руководитель или
  администратор.

## 2.0.0.2 — исправления после первой сборки (29 сентября 2026)

- Приход денег «на основании» абонемента подставляет «Отв. лицо ученика» из карточки ученика.
- Сумма абонемента или цена тарифа больше 99 999 999,99 больше не урезается молча — запись отклоняется с сообщением у поля.
- Урок без педагога или без учеников не проводится (отказ с сообщением у поля); урок-план без учеников по-прежнему записывается.
- Сообщение «касса уйдёт в минус» показывается у суммы документа.
- Все служебные объекты расширения собраны в подсистеме «Учёт занятий» (для сравнения и отбора в конфигураторе).

## 2.0.0.1 — первый выпуск «Учёта занятий 2.0» (29 сентября 2026)

Новая версия продукта «Учёт уроков»: вместо отдельной конфигурации LessonsManagement на БСП — расширение для
1С:УНФ 3.0, 1С:Бухгалтерии 3.0 и 1С:УТ 11.5 (платформа 8.3.24 и выше). **Ставится на чистые данные: перенос из
«Учёта уроков» не предусмотрен.** Промежуточных выпусков расширения («1.0», «1.1») не было. Работа шла 27–29.09.2026
(коммиты `70eb7d21` … `5a1e5444`).

**Поставка и совместимость**
- Все объекты — свои, с префиксом `УЗ_`, в подсистеме «Учёт занятий»; у хозяина заимствованы только
  «Организации», «Пользователи» и параметр сеанса «Текущий пользователь».
- Ни кода, ни объектов Библиотеки стандартных подсистем; печать встраивается в подменю «Печать» программы
  (если в ней есть БСП) или открывается своей формой.
- Кассы, статьи движения денег, приход и расход денег — свои объекты, проводок в бухгалтерии хозяина нет.
- Три роли: «Учёт занятий: менеджер», «…: руководитель», «…: педагог» (педагог видит только свои уроки и свою
  зарплату). Основной роли у расширения нет — права выдаёт администратор.
- Без модальных окон; справка F1 во всех формах продукта; помощник первой настройки в 7 шагов.
- Предупреждение в журналах, если у расширения включён безопасный режим (почта и обновление данных не работают).

**Правила учёта (как в типовых, решения 28.09.2026)**
- Урок не проводится раньше начала; будущий урок записывается планом. Длительность — до минуты.
- Урок по абонементу — цена абонемента, делённая на число занятий; хвост округления — на последний урок.
- Неявка «К оплате» расходует занятие, явка без «К оплате» — бесплатное занятие.
- Приостановка абонемента продлевает его срок; урок в дни паузы — отказ или предупреждение.
- Деньги учеников — раздельно по организациям; касса не уходит в минус ни расходом, ни перемещением.
- Зарплата: расчёт за период фиксирует вошедшие уроки, выплата — только педагогу и только по расчёту;
  «Прочий расход» не уменьшает долг педагогу; доплаты педагогу — документом «Начисление педагогам».
- Перевод ученика между группами — документом (состав группы на дату).
- Документ «Начисление ученику»; возврат по уроку возвращает только деньги.

**Новое против «Учёта уроков»**
- Свои даты запрета изменения (общая, по пользователю, скользящая «старше N дней»).
- Напоминания и оповещения; рассылка должникам по почте через свой сервер (с песочницей для проверки).
- РКО (КО-2), печать начисления бонусов; ПКО с реквизитами организации из её карточки.
- «Мои уроки» и «Моя зарплата» педагога; календарь уроков; панель ученика со сводкой.

**Исправлено** (каждое — тестом, `docs/проверки.md`): зарплата в двух расчётах; бонусы с пустой карты; единицы и
знак часов в «Списании остатков»; пересчёт цены урока при смене часов/даты/тарифа и скидка вне срока; «Изменение
уроков» без обновления движений; «К оплате» без тарифа проводилось с нулём; пересечения уроков только сообщались;
остатки не блокировались при проведении; возврат из карточки ученика не проводился; проверка должников и
«Переместить деньги» в расчёте зарплаты не работали; отчёт «Аналитика по ученикам» обращался к несуществующим
полям; выгрузка фото в жёсткую папку; ошибки панели ученика и приостановки абонемента.

**Не перенесено:** синхронизация с Google Календарём (позже заново), договоры контрагентов, история изменений
документов, перенос данных «Учёта уроков».
