# План: «Учёт уроков» (LM) → расширение «Учёт занятий» (УЗ_ext)

Составлен 27.09.2026 по описи конфигурации (три агента: карта продукта, аудит БСП, совместимость с УНФ/БП/УТ).

## Решения владельца (27.09.2026)

| | |
|---|---|
| Форма поставки | расширение `.cfe` поверх типовых **УНФ 3.0 / БП 3.0 / УТ 11.5** |
| БСП | **не используем** — ни кода, ни вызовов, ни объектов; идеи можно брать, код пишем свой |
| Данные клиентов | переносить **нечего**, старт с чистого листа |
| Название | «Учёт занятий»; расширение в 1С — `УЗ_ext`; префикс объектов — `УЗ_`; служебное имя (репо, файлы) — `LessonsManager` |

## Исходная точка (цифры описи)

- Конфигурация LessonsManagement 2.3.3.66, режим совместимости 8.3.14, БСП 3.1.
- Кода всего 562 тыс. строк, **из них продукта ≈13,6 тыс.** (90 модулей), остальное — БСП. Переносим только продукт.
- Продукт: 18 справочников, 10 документов, 5 регистров накопления, 3 регистра сведений, 9 отчётов, 7 обработок,
  2 журнала, 1 перечисление, 1 регламентное задание, роль `LM_Менеджер`.
- Ученики, педагоги, родители — свой справочник `LM_ФизЛица` (группы Педагоги/Ученики/Родители/Прочие),
  не Пользователи и не Контрагенты. Это удачно: от хозяина почти ничего не нужно.
- Прямых вызовов БСП активных ≈20 (15 модулей), плюс ≈30 скрытых зависимостей (формы, хуки, подписки, составы).
- Модальных вызовов 13 (`Вопрос`, `Предупреждение`, `ОткрытьМодально`) — в типовых модальность запрещена, переписать асинхронно.

## Архитектура расширения

**Заимствуем у хозяина — минимум, без реквизитов:**
- `Справочник.Организации` — есть во всех трёх; ИНН/префикс читать кодом через слой совместимости, реквизиты НЕ заимствовать
  (заимствованный реквизит с несовпавшим типом отключает всё расширение — урок ПЛ).
- `Справочник.Пользователи` — автор документа, адресат оповещений.
- Больше ничего. Роль `ПолныеПрава` не заимствуем (лишнее контролируемое свойство).

**Своё (`УЗ_`) вместо одноимённых типовых** — ни один не совпадает по структуре ни в одной конфигурации:

| В LM | В УЗ_ext | Почему не типовой |
|---|---|---|
| Кассы | `УЗ_Кассы` | в БП справочника касс нет (счёт 50), в УТ касса тянет ГФУ, кассовую книгу |
| СтатьиЗатрат | `УЗ_СтатьиДвиженияДенег` | в БП/УТ/УНФ три разных сущности с обязательным налоговым учётом |
| ПриходныйКассовыйОрдер | `УЗ_ПриходДенег` (печатная форма «ПКО») | типовые ПКО проводятся по регламентным регистрам хозяина — лезть в бухучёт покупателя нельзя |
| РасходныйКассовыйОрдер | `УЗ_РасходДенег` (печатная форма «РКО») | то же |
| ДоговорыКонтрагентов, LM_ВидыДоговоров | **не переносим** | мёртвые: ни код, ни реквизиты на них не ссылаются |

Мост к бухгалтерии хозяина (кнопка «создать ПКО в типовой») — позже, отдельной опцией, по образцу «Лист из продажи» в ПЛ.

**Слой совместимости** — общий модуль `УЗ_Среда` (образец — `ПЛ_Среда` и функции в менеджере `ПЛ_ПутевойЛист`):
`ТекущийПользователь` (поиск в `Пользователи` по `ИдентификаторПользователяИБ`, кэш на сеанс), `СообщитьПользователю(Текст, Поле, Отказ)`,
`НомерНаПечать`, `ЕстьРеквизит`, `ЗначениеРеквизита`, `ЕстьОбъектМетаданных`, `Паспорт()` (какая конфигурация под нами).
Правило: к объектам хозяина — только через `УЗ_Среда`.

**Параметры `Configuration.xml` расширения:** Purpose=AddOn, NamePrefix=`УЗ_`, режим совместимости расширения 8_3_24 (как ПЛ),
KeepMappingToExtendedConfigurationObjectsByIDs=true.

## Этапы

Каждый этап заканчивается проверкой, которая хоть раз покраснела на подложенной ошибке.

### Этап 0. Стенд и инструменты (≈полдня)
1. Выгрузить УНФ 3.0.12 (`Desktop\TEMP\UNF_3`) в XML — сейчас выгрузки УНФ нет; БП и УТ уже есть
   (`PRODIGY\cf_dump_bp` 3.0.196, `IMPORTTRADE\УТ_11_5` 11.5.26).
2. Тестовые базы: UNF_3, `Desktop\TEMP\БП`, `DemoTrd115` — **спросить Дмитрия**, можно ли занимать их (там стоит ПЛ_ext)
   или завести копии.
3. Взять набор `1c-knowledge\kit\tools`, быстрая сборка через агента конфигуратора (порт свободный, проверить владельца).
4. Офлайн-аудиты (секунды): зарезервированные слова; **гейт «ноль БСП»** — греп имён общих модулей, форм, картинок,
   стилей, определяемых типов БСП по исходникам расширения; имена только с `УЗ_`; дубли id на формах.
5. Папка исходников: `src_ext\` в этом репо, ветка `uz-ext`. Коммит/пуш — по слову владельца.

### Этап 1. Скелет расширения (≈полдня)
`Configuration.xml`, заимствованные Организации/Пользователи, язык (свой, не копировать чужой — урок: конфликт uuid),
подсистема `УЗ_УчетЗанятий` (Документы / Касса / Справочники / Отчеты / Настройки / Служебные), `УЗ_ОсновнаяРоль`,
модуль `УЗ_Среда`. **Проверка:** пустое расширение применяется на УНФ, БП и УТ, объект виден в `Метаданные` сеанса.

### Этап 2. Данные: справочники, перечисления, регистры (≈1–2 дня)
Перенос метаданных скриптом: `LM_` → `УЗ_`, **новые uuid**, типы ссылок перевести на новые имена.
Поскольку данных нет, **чиним типы сейчас — бесплатно** (потом это миграция):
- `LM_Урок.КоличествоЧасов` имеет тип **Дата** → Число;
- `LM_РасчетыПоЗарплате`: `Комментарий` строкой в **измерении** → в реквизит;
- `LM_Настройки`: фиктивное измерение `Реквизит1` → нормальный регистр/константы настроек;
- опечатка `Пермещение` → `Перемещение`; латинская «c» в `ПолучитьОстаткиЧаcовИСумм`.
**Проверка:** загрузка + `/CheckModules -Extension` + применение на трёх базах.

### Этап 3. Документы и код (≈3–4 дня)
Перенос модулей объектов/менеджеров/форм с заменой имён; все вызовы БСП → `УЗ_Среда`; 13 модальных вызовов → асинхронные
(`ПоказатьВопрос`, `ОписаниеОповещения`); ПКО/РКО → `УЗ_ПриходДенег`/`УЗ_РасходДенег` со своей печатью.
**Проверка:** гейт «ноль БСП» = 0; `/CheckModules -ThinClient -Server -Extension УЗ_ext`; тексты запросов — `НайтиПараметры()`
на трёх базах с самотестом 3 из 3.

### Этап 4. Замены механизмов БСП (≈3–4 дня)
По таблице выше, от дорогого к дешёвому: `УЗ_ФормаОтчета` → даты запрета → оповещения/напоминания → обработчики обновления →
роль → картинки/стили → связанные документы, панель отчётов.

### Этап 5. Проверки (≈2 дня, дальше — постоянно)
- COM-тесты ядра в одном сеансе (урок с учениками → списание абонемента, оплата → касса, начисление педагогу → расчёт ЗП →
  выдача, бонусы по дисконтной карте, должники) — на УНФ, БП, УТ. Каждой проверке — мутация.
- Права: живой вход сотрудника с базовой ролью хозяина + `УЗ_ОсновнаяРоль`.
- Интерфейс глазами: веб-клиент во встроенном браузере, все формы продукта, со второго открытия.

### Этап 6. Демо и выпуск
- Своя пустышка без БСП (как «ПутевыеЛистыДемо») + демо-данные — .dt с типовыми распространять нельзя.
- Справка F1 (`Ext/Help.xml`), версия расширения, инструкция, карточка Инфостарта.
- Видеопрезентация с озвучкой (ElevenLabs): сценарий + кадры веб-клиента на демо-базе.

## Кто что делает

- **Claude** — перенос, код, слой совместимости, проверки, сборка.
- **Codex** — иконки и картинки `УЗ_*` взамен ~25 картинок БСП (этап 4), логотип, баннеры; механическая адаптация
  форм по заданию. Всё за ним проверяется (урок ПЛ 23.09: выдумки в справке F1) — принимаем только после проверки.
- **ElevenLabs** — озвучка видеопрезентации (этап 6).

**Итого до работающего расширения на трёх конфигурациях — ориентировочно 2–3 недели работы.**

## Решения по открытым вопросам (владелец, 27.09.2026)

1. Google Календарь — в первой волне не переносим, позже сделаем заново.
2. Почта ученикам — своя, средствами платформы (ИнтернетПочта); настройки SMTP владелец введёт позже.
3. Печать — встраиваемся в подменю «Печать» типовой, переиспользуя БСП покупателя (только через УЗ_Среда и Вычислить
   после проверки метаданных); без БСП у хозяина — своя печать. Свою копию БСП не поставляем.
4. Тестовые базы UNF_3 / БП / DemoTrd115 — можно, но не мешать Путевым листам; при риске — отдельные копии.

Список недоделок продукта, найденных при описи, — `docs/недоделки.md`.
