# Независимое код-ревью расширения УЗ_ext

## 5 главных находок

1. `src_ext\Documents\УЗ_Урок\Ext\ObjectModule.bsl:70,173-208` - списание абонементов проверяет остатки через `Остатки()` без управляемой блокировки, затем пишет расход. При одновременном проведении двух уроков один абонемент можно списать сверх лимита.
2. `src_ext\Documents\УЗ_Урок\Ext\ManagerModule.bsl:236-237,273-274,304-342` - пересечения педагога/помещения ищутся неполным условием интервалов и только выводят сообщения, не запрещая проведение. Возможны двойные бронирования.
3. `src_ext\Documents\УЗ_ПриходДенег\Ext\ObjectModule.bsl:43-71,126-135` - списание бонусов по дисконтной карте читает остаток без блокировки и сразу добавляет расход. Две оплаты могут одновременно списать одни и те же бонусы.
4. `src_ext\CommonModules\УЗ_ОбновлениеДанных\Ext\Module.bsl:41,55-64,92,202` и `src_ext\CommonModules\УЗ_ДатыЗапрета\Ext\Module.bsl:166-179,217-219` - привилегированный режим включается без гарантированного выключения в `Исключение`/`finally`-эквиваленте; для расширения это особенно рискованно из-за безопасного режима.
5. `src_ext\Documents\УЗ_Урок\Forms\ПомощникСозданияУроков\Ext\Form\Module.bsl:85,113,373,614,851,932` - после переноса `УЗ_Урок.КоличествоЧасов` из `xs:dateTime` в `xs:decimal` часть помощника продолжает считать длительность как дату от `'00010101'`. Это миграционный долг с риском неверных дат/длительности в массовом создании уроков.
