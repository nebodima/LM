# Сценарии пользователей по ролям (тест-менеджер 1С)

Настоящий тонкий клиент под пользователем роли, управляемый штатным механизмом платформы (`/TESTCLIENT` +
`/TESTMANAGER`, `ТестируемоеПриложение`, `ТестируемаяФорма`, `ТестируемоеПолеФормы`, `ТестируемаяКнопкаФормы`).
Видит то, чего не видят COM-тесты: падение формы при открытии, окно «непредвиденная ситуация», скрытые поля,
отказ прав на экране, оповещение об ошибке применения расширения.

## Запуск

    python tools\сценарии\прогон_сценариев.py                      все роли на C:\1c_bases\UZ_BP_C (~90–100 с)
    python tools\сценарии\прогон_сценариев.py --роли=педагог       одна роль
    python tools\сценарии\прогон_сценариев.py --самопроверка       заведомо ложные шаги обязаны покраснеть (6 из 6)
    python tools\сценарии\прогон_сценариев.py --зонд=e1cib/data/Документ.УЗ_ПриходДенег --роли=менеджер
                                                                    что видит клиент: окна, формы, имена элементов

Ключи: `--база=` (по умолчанию `C:\1c_bases\UZ_BP_C`), `--админ=` (пользователь COM, для БП — `1`),
`--база-менеджера=` (пустая база менеджера, по умолчанию `C:\1c_bases\UZ_TM`, создаётся сама), `--видно` (окна не
уводить за экран), `--подробно` (все шаги), `--замер` (время старта клиента), `--без-уборки`,
`--убрать-пользователей`. Код выхода 0 — всё зелёное (для `--самопроверка` — все ложные шаги пойманы).

Перед прогоном база должна быть обновлена: `pwsh -File tools\деплой.ps1 -СвояБаза C:\1c_bases\UZ_BP_C -Пользователь 1`.
Условие платформы: в `C:\Program Files\1cv8\conf\conf.cfg` строка `DisableUnsafeActionProtection=.*` (иначе модальный
вопрос об открытии внешней обработки).

## Как устроено

* `сценарии.json` — сценарии ДАННЫМИ, по ролям (`руководитель`, `менеджер`, `педагог`, `самопроверка`); шаг — объект
  с действием `д`: `открыть` (навигационная ссылка, `форма` — дождаться формы; в заголовке `*` — любые символы),
  `форма`, `поле` (ввод текста; ссылочное подбирается по вводу), `флажок`, `кнопка`, `страница`, `строка` (строка
  таблицы формы), `выбрать_строку` (ПерейтиКСтроке по заголовкам видимых колонок, `открыть`), `проверить`
  (`равно`/`содержит`/`не_пусто`; поле или декорация), `скрыт` (элемента нет или не виден), `сообщение`,
  `без_ошибок` (ни сообщений, ни окна ошибки платформы), `отказ` (ссылка → «Недостаточно прав»/«Нарушение прав
  доступа»), `ответ`, `закрыть`, `ждать`, `не_реализовано` (шаг описан, не сделан — в итоге с причиной), `зонд`.
  `{имя}` в шаге — переменная (`сегодня`, `сегодня_кратко`, `время`, `чужой_урок`), см. `данные.переменные`.
* `УЗ_Сценарии` — исходники исполнителя (внешняя обработка, код в модуле формы, клиентский). Собирается сам, когда
  исходники новее `.epf`: пакетный конфигуратор в пустой базе менеджера. Перед сборкой — гейт: имена процедур не
  заняты методами клиента/формы (`ВвестиЗначение` не компилировалось на клиенте) и компиляция того же текста модулем
  объекта через COM (номера строк — как в модуле формы).
* `прогон_сценариев.py` — COM под администратором (пользователи ролей, урок чужого педагога) → роли строго по очереди:
  клиент роли + менеджер = 2 сеанса, окна за экраном → итоги → уборка COM (всё новое за прогон по снимку ссылок,
  организации касс и настройки учёта — как были). Снимок «до» лежит в `итоги\снимок_до_прогона.dat`, пока
  уборка не прошла: прерванный прогон (нет лицензии, Ctrl+C) или `--без-уборки` — следующий прогон начинает с уборки
  по нему (иначе мусор прошлого прогона попадал в новый снимок «до», и помощник первого запуска находил всё «уже
  есть» — 28.09.2026). Предопределённые элементы (касса ОсновнаяКасса) уборка не удаляет. Провал сценария останавливает исполнитель (закрыть изменённую
  форму нельзя — модальный вопрос), остальные сценарии роли идут в новом клиенте.
* `данные.py` — подготовка и уборка; `окна.py` — окна за экран и снимок окна (PrintWindow, работает за экраном).
* Итоги — `tools\сценарии\итоги\` (в .gitignore): `итог.txt`, `итог.json`, снимки `роль_запуск_N.png` на каждый провал,
  журналы клиента и менеджера (`/Out`). После прогона журнал регистрации проверяется на ошибки применения
  расширения при входе сотрудников.

## Бюджеты

Прогон трёх ролей ≤ 120 с (факт 28.09.2026: 88–100 с), роль ≤ 60 с (факт 22–28 с, из них ~15 с — старт клиента БП),
шаг ≤ 10 с (дольше — «ДОЛГО» в итоге). Таймаут роли — 3× бюджета.
